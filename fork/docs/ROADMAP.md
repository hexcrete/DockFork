## Explicit Quit Actions

October 18 implementation, user reports working: normal **Quit App** always requests normal termination, including Option-based sessions and Close configured to quit an app. **Force Quit App** is a separate shared action that may discard unsaved changes. The inherited behavior treated any held Option as Force Quit, including required shortcut/session modifiers; that implicit preview-action override is removed with the user's approval. Existing stored Quit assignments and defaults are preserved. The documented Command+Option+right-click Dock-icon Quick Quit gesture remains unchanged.

The explicit action reuses shared assignments, native menus, destructive styling, shortcut hints, action feedback and app-wide batch targeting. When Quit overflows into a More menu, its explicit Force Quit alternative appears beside it. No new toolbar button or shortcut is enabled by default. Windowless apps are eligible, requests are deduplicated by PID, and existing termination notifications clear selected entries. Both actions are request acknowledgements, not verified-exit results. Labels and execution no longer consult transient modifiers. Existing request refusal, cancellation and presentation cleanup paths remain in use.

AppleScript adds `quit app` and `force quit app` using existing window IDs, `"active"` and ordered lists of window IDs to identify the owning apps. Both use the shared batch executor and remain feedback-free. The standard `quit` command still quits DockFork itself. Names/bundle IDs/PIDs are not new inputs to these commands, and a windowless app without a resolvable window ID is not a script target. Scripting descriptions and generated examples warn that Force Quit may discard unsaved changes.

All nine regression suites and the unlocked native presenter check pass. Production-source regression tests use inert apps, not real termination. Native AppleScript compilation verifies the installed dictionary without executing commands. Manual destructive checks must use disposable apps/windows with explicit permission. The user reports the implementation working and final source review found no blocking issues. Exhaustive session/menu and agent-operated destructive verification remain pending; this is separate from the earlier action-feedback implementation and not a published release.
