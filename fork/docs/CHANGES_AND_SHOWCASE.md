## Development: Confirmed Tiling and Main-Window Activation

October 15 investigation: Brave diagnostics showed frame changes without the intended placement. Authorized agent testing on one Brave window reproduced accepted AX requests that did not yield the requested frame; matching titles were not used to identify the target. Brave retained Enhanced UI with VoiceOver off. AX writes in that mode can animate and interfere with coordinated position/size updates. The shared frame helper now temporarily disables that mode only when originally enabled, restores it synchronously before returning, resizes before positioning, and finishes resizing at the new position only if the accepted size still differs. It avoids redundant size writes when the requested size already matches. Brave can apply the mode write while returning notImplemented, so restoration does not depend on its status. No setting, browser-specific exception or permanent accessibility-mode change is added.

Group tiling now reads back the real frame before declaring placement successful and raising the window. One synchronous size/position transaction is checked immediately. Only a mismatch gets one asynchronous 100ms wait and one read-back, with no delayed reapplication or retry loop. An unusually slow app can be reported as failed before finishing; there is no added wait on immediate success. Cancellation/request-token checks stop stale work, and one targeted preview refresh follows accepted changes. A partially accepted size/position operation also retains the existing immediate reconciliation instead of waiting for a missing confirmation. Unresponsive AX calls can still add their existing timeout cost. Minimum-size constraints or other refused placements report failure rather than optimistic success; successful partial group changes are not rolled back. Group-drag placement retains its existing synchronous positioning behavior; the shared group coordinator now awaits either placement callback safely.

The shared activation helper also sets the window's AXMain Boolean instead of incorrectly writing a Boolean to the application-level AXMainWindow attribute. Both the old frame-write order and incorrect activation attribute exist in the incorporated upstream source; the fork's group tiling reused them and lacked frame read-back. Existing menu/input routing and preference-controlled foregrounding remain intact. Added failure diagnostics use PID/window ID and frame/status information, not window titles. Restoring Enhanced UI can have app-specific cost during an action; no idle work, extra global discovery, event monitor or repeating timer is added.

A permanent app-size constraint still reports failure and is not foregrounded as a successful tile.
