# DockFork: Changes and Showcase

DockFork is a fork of [DockDoor by ejbills](https://github.com/ejbills/DockDoor). DockDoor supplies the original application, Dock previews, Window Switcher, Cmd+Tab integration, widgets, and many settings. This guide describes the fork's additions and changes, not the origin of those existing capabilities.

**Publication:** [DockFork 0.1.0](https://github.com/hexcrete/DockFork/releases/tag/v0.1.0) is published as a prerelease from `36e635e`. The user reported successful testing on additional Macs running macOS 27 after local transfer. Downloaded/quarantined installation validation remains pending. Local development uses certificate-signed DockFork at the fixed, gitignored `fork/dist/dev/DockFork.app` path. Historical candidate checks below do not describe later development builds.

## Development: Automatic Tiling

Phase 4 is committed as `6ae187c`; manual verification was reported successful October 13 and the final source review found no blocking issues. This development change is not in the published 0.1.0 release. Auto Tile Selected Windows is available in the shared shortcut/gesture/mouse-action catalog and preview Arrange menus. It uses checked windows, including when keyboard highlighting is absent, and fills a single targeted window when none are checked. Menu-bar Arrange offers Auto Tile Window for its individual target; preview menus also offer Add/Remove from Selection. Half/Quarter actions tile multiple checked windows; individual-window Half/Quarter behavior remains unchanged. Menu-bar window menus remain individual.

Tiling targets the current Desktop and display under the pointer, using its visible frame. The first checked eligible window leads. One fills the display, two use halves, three use a leading half and two opposite quarters, and four use quarters. Half actions choose the leading edge; Quarter actions with two/three windows use quarter cells and leave unused cells empty. Grid constraints take precedence when the requested shape cannot fit the permitted rows/columns. Larger groups use a display-aspect-aware grid with an expanded short final row. Maximum tiling rows/columns are independently configurable from 1 to 6, both default 2. Values above 3 show a display/minimum-size warning. A 1x1 limit still moves without resizing. Overflow repeats the same algorithm in ordered batches up to the configured capacity; a final single member fills the display for Auto Tile or uses the requested half/quarter. macOS may adjust windows during Space assignment, and apps can enforce minimum sizes.

Tiling and group dragging share one confirmed-move/reveal/placement worker. Fullscreen, windowless, terminated and multi-Desktop sources are rejected; successful eligible members retain checking order. Layout is computed once after confirmation/reveal, not during preview rendering or pointer movement. Placement uses the explicit destination screen and reports AX acceptance/partial failure. Tiling raises all successfully placed windows when Bring moved/resized windows to front is enabled, in reverse checking order so the leading member finishes in front. This occurs in the placement worker, not a container-view completion guard; Off makes no explicit activation requests. Drag drops retain their required raising. Existing targeted preview recapture and fullscreen image safeguards remain intact. Failed members chime/log; successful moves are not rolled back.

Validation: 45 isolated tests passed, including 12,960 count/direction/grid-limit combinations with bounds checks and overlap checks within each batch. Overlap between overflow batches is intentional. Five simulated production group-drop checks passed after the shared-worker extraction, plus five simulated production tiling checks covering repeated overflow, foreground raising On/Off, 1x1 move-only behavior, single fill and directional quarters. These do not establish live macOS placement or multi-display behavior. The signed Debug build, exact-path relaunch, source/dictionary correspondence and diff checks passed. Relaunch required one retry after Launch Services error -600. User manual verification passed October 13; no exhaustive display or feature coverage is inferred. Full Xcode tests remain pending. The separate scripting follow-up precedes drop-to-tile; neither is part of this implementation.

### Tiling and Selection Scripting

New native commands reuse the same tiling operation and checked-selection model. Existing Apple event codes/commands are unchanged. Ordered IDs are deduplicated without changing their first occurrence. Omitting IDs uses checked windows, or the active window when none are checked. Scripts wait for completion with one bounded reply and report partial failures without rolling back successful changes. The tiling deadline is 15 seconds; it cancels remaining work, not changes already made.

```applescript
tell application "DockFork"
    auto tile window "active"
    tile windows {"12345", "67890"} to "right" with bringing to front
    tile windows without bringing to front
    toggle window selection "active"
end tell
```

The last command requires multi-window selection enabled and an open preview session. Direction defaults to `"auto"`; other directions use the existing position names. The foreground argument is optional and otherwise uses the configured preference. These commands and examples are included in the app's scripting dictionary/generated help. Native command compilation, generated help and invalid single/list/empty-list replies passed on the running signed development build without modifying real windows. The dictionary uses a typed list of text for ID arrays, not an untyped list receiver. Successful real-window scripting and deadline races still require manual verification.

## Development: Drop-to-Tile

Phase 5 is committed as `7a6ec7d`. User verification passed October 13 for the drop behavior and the independent setting/shared-highlight follow-up. Enable dragging windows together to tile them is under Gestures & Keybinds > Mouse Actions, defaults Off, and is independent of multi-window selection. When enabled, release a dragged preview over another real preview to combine the target window/group first, then dragged windows in their original order, deduplicated by PID/window ID. Checked drag initiators retain their start-of-drag snapshot; unchecked initiators drag one window. A target already in the dragged group is a silent no-op. Checkbox membership is not required for single-window drops. With the feature disabled, ordinary drag placement remains unchanged.

Regular and Compact Mode use the existing shared gesture/release path in Dock, Cmd+Tab and Window Switcher. The current grid resolves tracking/release points from its existing card frames and live scroll offset, including layer-only edge scrolling, and checks the rendered identity against the current row. Gaps/widgets do not become tiling targets; windowless/fullscreen/multi-Desktop/terminated targets are unavailable. Mock/disabled grids do not register live target lookup. The grid link is weak and replacement-safe on teardown. Internal preview targets reuse the external file-drop highlight renderer, without activating file spring-loading. Highlight state changes only when its PID/window ID changes; self/group, windowless, terminated and known-fullscreen targets do not highlight. Release, cancellation, disabled settings and new sessions clear the state. Tracking performs cached hit-testing only; Space/AX validation stays at release. No hover monitor or per-frame geometry measurement is added.

Use the target window's Desktop and display, not the preview panel's location. With separate Spaces, resolve the display from managed topology; with shared Spaces, use the target's recorded physical monitor, with a safe single-display fallback. Missing Desktop/display information rejects the drop rather than choosing an unrelated monitor. Confirm cross-Space moves before reveal/placement, then reuse Auto Tile's limits, overflow and screenshot safeguards. A 1x1 limit moves without explicit resizing. All three drag paths always raise successful windows regardless of Bring moved/resized windows to front. Successful tile drops raise the ordered windows with the leading target first and dismiss through the existing callback. Partial failures keep the container open and report failed identities; successful changes remain. Self-drops do not dismiss. The ghost closes immediately on release, and container dismissal cancels pending work. Hover activation is suppressed during internal preview dragging; external-item spring-loading remains separate.

## Newly discovered window focus recency

October 14 development: notification registration could return cannotComplete almost immediately while a new app was starting. The incorporated upstream code treated every such response as a hang and deferred discovery for five seconds. During that delay, an app could appear as a windowless placeholder at the bottom of the switcher. Registration now shares the general AX helper's existing measured-time rule: only a cannotComplete response lasting at least 0.5 seconds triggers backoff. An obsolete failed observer cannot mark its replacement unresponsive. Ordinary launch/creation discovery supplies retries; no new timer or retry loop is added.

A second inherited race dropped focus updates before the target window entered the cache. The narrowed implementation preserves only explicitly identified PID/window-ID focus timestamps, applies them on cache insertion, and prevents older callbacks from reducing cached recency. Focus notifications reuse the already-resolved AX window immediately while the app is active; workspace activation retains its original event time. Pending window timestamps expire after 30 seconds, are capped at 128, and clear on app/cache purge. Untouched startup restoration and screenshot validation remain unchanged.

Earlier timestamp-only attempts failed user tests. An app-level inferred-focus fallback was subsequently removed after review found false-focus inference, stale activation consumption and redundant AX queries. The final implementation does not infer window focus from app activation or from a sole cached window and does not store unresolved app-level activations.

Before narrowing, a fresh System Settings launch registered a real window and fresh focus within about 0.87 seconds without false backoff, and the user reported the root-cause correction working. After narrowing, 64 isolated regression tests passed. The narrowed signed Debug build, strict signature/binary checks and required-path relaunch passed after a Launch Services retry. A fresh Calculator launch produced one real cached window with a focus timestamp about 0.21 seconds after launch, without false backoff or inferred app focus. Calculator was left running without changing its inputs. The user reports the narrowed fix working much better. Final correctness, lock-order, lifecycle and simplification review found no blocking issues; the 64-test isolated suite passed again. Full Xcode tests, exhaustive runtime coverage and whole-app profiling remain unrun. This is a targeted discovery/focus race fix, not a broader MRU rewrite. It is not part of the published 0.1.0 prerelease.
